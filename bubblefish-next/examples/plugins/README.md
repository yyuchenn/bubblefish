# 示例插件

这些示例尚未发布，版本统一保持 `0.1.0`。

这些插件通过公开 SDK 验证安装、图片与标记操作、历史、事件和拦截。同一插件可以组合多种能力。实际 OCR 和在线翻译分别使用 [Kha White OCR](../../plugins/kha-white-ocr/README.md) 和 [DeepSeek 翻译](../../plugins/deepseek-translation/README.md)。

在 `bubblefish-next` 中执行：

```sh
npm run plugin:pack -- examples/plugins/document-toolbox
npm run plugin:pack -- examples/plugins/history-inspector
npm run plugin:pack -- examples/plugins/edit-guard
```

产物位于 `dist/plugins/`。在应用左侧“插件管理”中安装 `.bfplugin` 并启用。工具箱自动列入底部 Tab，其他示例可从插件卡片打开声明式面板。普通主实例按首次调用激活，具有提交前钩子的插件会预热独立的 hooks 实例。先创建含有图片的项目，再按下面步骤操作。

编辑检查插件为“检查编辑插件主实例”提供成功摘要，在插件卡片中可展开完整返回数据。通过其面板 SDK 发起相同查询时，结果只显示在面板内。工具箱提供单个底部 Tab，历史检查器使用声明式弹窗入口。

三个示例面板使用公开的 `--bf-panel-*` 变量，文字、背景和控件跟随宿主当前主题，布局仍由插件定义。宿主为网页和桌面注入共享基础样式；旧安装包也能在更新应用后适配，无需卸载。实时切换主题保留面板输入、滚动和后台操作，主题不进入配置或历史。面板继续只连接 `event.ports[0]` 的 SDK API，第二个端口由宿主主题脚本管理。变量示例和加载确认机制见 [插件开发文档](../../docs/PLUGINS.md#主题与基础样式)。

## 图片与标记工具箱

安装并启用 `example.document-toolbox.bfplugin` 后，底栏自动出现一个“图片与标记工具箱”Tab；首次选中时才加载页面，从插件卡片打开也会选中同一个 Tab。工具箱 ID 仍为 `example.document-toolbox`，版本仍为 `0.1.0`。若已安装旧工具箱，请先卸载，再按上面的原有命令重新打包、安装并启用；更新宿主不会替换已安装的插件包。

工具箱跟随画布的当前项目、图片和标记。工具箱内的图片、标记下拉框只临时改变本面板的操作目标，不改变画布选择；下一次画布选择变化时恢复跟随。切换主题不会重置这个临时选择。

未提交的文件名、几何、样式、译文与辅助文本等草稿按项目、图片和标记目标保留在当前面板会话中，切换目标再返回、切换 Tab 或收起底栏都可继续编辑。点击“刷新当前项目”会丢弃当前目标的草稿，重新读取已提交内容，其他目标的草稿仍保留。刷新整个应用页面或卸载插件会结束该面板会话。切换图片或项目时，上传文件选择与图片预览会清空，避免将上一张图片的文件或预览用于新目标。

点击操作按钮时，工具箱固定本次操作的项目、图片、标记和输入；即使读取或上传尚未完成就切换画布，操作仍针对点击时的目标，不会转而修改新目标，迟到的读取结果也不会覆盖新目标的表单或预览。

1. 点击“预览完整原图”读取原始编码字节；调整归一化坐标并预览裁剪 PNG。读取元数据时不会泄露磁盘路径。
2. 选择本地图片后，可以上传为新图片或替换当前图片像素。替换保留已有标记坐标。还可以复制原图、修改文件名、反转顺序和删除页面。
3. 新增点／矩形标记，修改几何、覆盖文字与横排样式，反转标记顺序或删除标记。
4. 写入纯文本或完整 RichText JSON；读取、更新、清空原文与机器译文。新标记的 `bunnyCache.toolboxField` 演示更新辅助字段时保留未知内容。
5. 点击“执行图片与标记批事务”：先暂存图片，再用预分配的稳定 ID 创建图片、创建标记、写入富文本及辅助字段。一次撤销恢复整个事务。

每个单项修改也调用 `document.transaction`。图片字节通过 `images.stage` 的二进制附件上传，事务只引用 `stagedResource`，不接受插件声称的图片尺寸或校验值。后台修改不会抢走应用编辑器焦点。

## 历史与事件检查器

安装 `example.history-inspector.bfplugin`，打开“历史与事件检查器”。

- 两栈以栈顶优先分页显示标签、稳定 `entryId`、来源以及前后状态 ID。页首显示 `historyRevision` 和两栈总数；后续输入合并会保留条目 ID 并增加版本。
- “压入事务”通过 `history.push` 原子新增标记及译文；“弹出 undo／redo 栈顶”通过 `history.pop` 移动真实历史记录。“撤销／重做”调用相应快捷接口。
- 控制历史时带上最近读取的真实栈顶 ID 和历史版本，防止在异步编辑后误撤销另一条记录。冲突后重新读取即可重试。
- 日志订阅图片、标记、译文、辅助字段、历史和事务完成事件，展示来源及事务信息。默认不接收自身操作；勾选“包含本插件发起的变更”后再压入事务可比较过滤效果。

历史 API 不提供快照读取、任意删除中间记录或插件定义的撤销回调。

## 编辑检查插件

安装并启用 `example.edit-guard.bfplugin`，打开“编辑检查示例”。同一个包在 `ctx.runtimeRole === 'hooks'` 时注册钩子，在 `main` 角色注册翻译 provider 与检查主实例命令。

1. 向选中标记写入 `测试１２３`，实际译文为 `测试123`。同样可直接在应用译文／原文编辑器输入；RichText 的样式标记会保留。
2. 写入 `１２３ [BLOCK]`，第二个钩子拒绝提交。拒绝原因含 `123 [BLOCK]`，可验证规范化钩子（-10）先于规则钩子（10）。应用中的编辑被拒绝时可从恢复草稿取回输入。
3. 设置 400ms 延迟，再提交一次。超过默认单钩子 250ms 预算后，宿主继续提交并暂停此插件的拦截能力。点击“检查主实例仍可运行”，或在应用中使用“编辑检查：主实例示例翻译”，验证主实例未被停止。
4. 将延迟恢复为 0ms，在插件管理中点击“恢复拦截”，再次测试全角数字转换。

撤销／重做不经过检查钩子。配置只属于插件；钩子不能嵌套提交事务或控制历史。面板关闭不会停止 provider 或 hooks 实例。

## Rust WASM 和原生进程示例

```sh
npm run build:web
node crates/plugin-sdk/examples/build-example.mjs
```

构建生成 `.cache/plugin-sdk-example/example.echo.bfplugin`，包含真实 Rust WASM 与当前主机原生可执行文件。浏览器运行 WASM，桌面优先使用匹配 Rust target 的原生入口。需要匹配 Cargo.lock 的 wasm-bindgen CLI；`build:web` 会准备其缓存。只打包网页入口时，给示例脚本传 `--web-only`。

Rust 示例用于验证握手、注册、图片附件、进度、翻译、文档事务、历史和双角色拦截，不执行真实 OCR。不同操作系统及 CPU 架构的原生程序需要分别构建。

SDK 说明见 [Rust SDK](../../crates/plugin-sdk/README.md) 和 [插件开发协议](../../docs/PLUGINS.md)。
